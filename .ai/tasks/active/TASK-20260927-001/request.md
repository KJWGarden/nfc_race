# User Request

## Original Intent

NFC 워킹 레이스(CHECKPOINT)를 실제 사용자들이 사용할 수 있도록 운영 가능한 상태로 만든다.

## Explicit Requirements

1. 저장소를 Supabase로 연동한다 (현재 `data/db.json` 파일 저장 대체).
2. 규모: 참가자 100-200명, 최대 300명.
3. 부정 태깅 방지는 L4로 진행한다: NTAG 424 DNA 태그의 SUN(Secure Unique NFC) 동적 URL을 서버에서 검증하고, 이미 사용된 태그 URL은 거부한다.
   - 태그는 지점당 1개이며 모든 팀이 같은 태그를 찍는다.
4. 태그는 팀당 한 명만 찍으면 팀 전체가 인정된다 (현재 팀 단위 기록 규칙 유지).
5. 배포 대상: Vercel.
6. 실시간 갱신: 참가자 화면은 폴링, 관리자 화면만 Supabase Realtime.
7. NFC가 안 되는 휴대폰의 참가자는 팀원 폰으로 찍는다 (별도 대체 기능 없음).
8. 저장소를 독립 git 저장소(dev 브랜치)로 분리한다 — 완료됨 (`git init -b dev`, 커밋 없음).

9. (사용자 결정 2026-09-27) L4 적용 시 정적 토큰/지점 QR/태그 코드 직접 입력/일반 NFC(UID만) 경로로 지점을 인정하는 기능을 모두 끈다. 참가용 초대 QR은 유지한다.
10. (사용자 결정) 기준 카운터는 관리자가 레이스 시작 직전에 각 태그를 찍어 수동 갱신하는 방식으로 한다. 갱신 이전에 수집된 URL은 무효, 갱신 후 시작 전 탭은 유효.
11. (사용자 결정) 운영 보안 강화를 이번 작업에 포함한다:
    - 운영 환경에서 ADMIN_PASSWORD / APP_SECRET가 없거나 기본값이면 동작하지 않게 차단
    - 관리자 로그인 시도 제한
    - 참가자 재입장 기능 (쿠키를 잃은 참가자가 팀 코드와 이름으로 기존 참가자로 다시 들어옴)
12. (사용자 결정) 참가자 재입장에는 시도 횟수 제한을 적용하지 않는다 (추측 위험은 문서화만).
13. (사용자 결정) 관리자 모드 추가: 관리자로 로그인한 폰으로 태그를 찍으면 참가자 태깅 대신 '태그 등록 / 기준값 갱신' 화면이 뜬다. iPhone과 Android 모두에서 기준값 갱신이 가능해야 한다.

## Explicit Constraints

- Supabase 프로젝트는 아직 없다. 실제 연결 검증은 프로젝트 생성 후 가능하다.
- L2(지점 간 최소 이동 시간)는 선택되지 않았다.
- git 커밋은 사용자 요청 시에만 한다.

## Open Questions

- 기존 `data/db.json` 데이터(데모 세션 등)를 Supabase로 이관할 필요가 있는지는 언급되지 않았다.
